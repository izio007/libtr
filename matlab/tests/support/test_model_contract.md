# Пошаговый движок ансамблевых испытаний

Основание: запрос рефакторинга по примеру runtime/elintmodellib (em.h,
emtypes.h). Заимствуется разделение состояния модели, алгоритма и метрик,
а не C99-реализация, глобальные регистры или физические константы примера.

Контекст: observations (P, alpha, beta, va, vb), algorithm (function handle),
truth, cursor и result. Входные наблюдения общие для сравниваемых алгоритмов.
init проверяет размеры и выделяет результаты; step исполняет ровно одно
наблюдение; result разрешён только после завершения и вычисляет метрики.
Индекс наблюдения не является физическим временем. Движок не генерирует шум,
не пишет файлы, не рисует и не меняет rng сам; побочные эффекты переданного
алгоритма остаются ответственностью его контракта.

@CRITERION TEST-MODEL-001: два контекста исполняются независимо; копия контекста
позволяет продолжить расчёт с теми же входами. За концом step отклоняется.
@CRITERION TEST-MODEL-002: старый service_run_ensemble сохраняет сигнатуру,
поля результата и правила статусов 0/1/2, NaN, исключений и условных метрик.
Ошибки исполнения не останавливают последующие наблюдения. Текст стека
исключения может измениться из-за новых функций и не сравнивается побитово.
@CRITERION TEST-MODEL-003: незавершённый результат нельзя выдать за завершённый;
размеры входов отклоняются до запуска оператора; успешные массивы сравниваются
с независимым прямым вызовом каждого из LLS/WLLS/GN/GNP.

Это первый срез: ансамбль статических наблюдений. Траекторный проигрыватель,
состояние последовательного алгоритма и общий отчёт checks — отдельные этапы.

## Траекторное проигрывание безынерционных оценивателей

test_trajectory_init принимает time [1 x N] в секундах (конечный, строго
возрастающий), truth [3 x N] и P [3 x M x N] либо постоянную P [3 x M].
Наблюдения alpha/beta [M x N] уже сформированы; дисперсии постоянны [M x 1].
Исполнение использует общий test_model_step. Индекс cursor и current_time
различаются; до первого шага current_time=NaN. Текущее время означает
потреблённый кадр, даже если оцениватель завершился отказом.
Метрики траектории — условные моменты ошибки samples-truth по успешным
кадрам, не ковариация положения движущейся цели и не ансамбль одного такта.
Физическая интерпретация временного усреднения задаётся сценарием.

@CRITERION TEST-TRAJECTORY-001: каждый кадр четырёх оценивателей совпадает
с прямым вызовом на тех же наблюдениях и положении постов; ансамблевый API
не меняется. Известная безошумная траектория восстанавливается до 1e-8 м.
@CRITERION TEST-TRAJECTORY-002: повтор/NaN/убывание времени и неверная
размерность истины отклоняются до исполнения. Постоянные и покадровые посты
эквивалентны при одинаковой геометрии.
@CRITERION TEST-TRAJECTORY-003: ошибки не становятся нулевыми отклонениями;
независимые контексты, копирование и защита незавершённого результата сохраняются.

## Последовательный алгоритм

test_stateful_init строит траекторный контекст с явным algorithm_state.
Оператор вызывается как [status,x,next]=step(state,frame), где frame содержит
index, time (секунды), P, alpha, beta, va, vb — но не истину.
Результат адаптера остаётся позиционным: double [3 x 1], статусы 0/1/2.
Иные выходы, например скалярный filter2win, требуют отдельного адаптера;
их статусы нельзя автоматически трактовать как позиционные.

Состояние — дерево чисел, logical, char, struct и cell; объекты, function
handles и внешние ресурсы запрещены. Оператор не меняет внешнее состояние.
После корректного выхода next принимается даже при штатном отказе 1/2:
алгоритм сам определяет, нужно ли вернуть прежнее состояние. При исключении
или нарушении контракта выхода состояние не публикуется; кадр потреблён,
нарушение отмечено. Это не откатывает внешние эффекты недопустимого оператора.

@CRITERION TEST-STATE-001: независимость двух экземпляров и воспроизводимое
продолжение с копии; frame не содержит truth, время и геометрия совпадают с входом.
@CRITERION TEST-STATE-002: штатный отказ может обновить состояние; исключение,
неверный next и нарушение контракта x оставляют прежнее состояние.
@CRITERION TEST-STATE-003: прежние ансамблевые и траекторные проверки проходят.

## Скалярный filter2win

test_filter_init принимает cfg, ctx, time, measurement, missing, truth
как явные входы; временные ряды — строки одинаковой длины. Кадр содержит
index/time/measurement/missing, без истины и фиктивных углов/координат.
Адаптер test_filter_step возвращает скаляр и новое состояние cfg/ctx.
Статус адаптера 0 означает доступное конечное значение; 2 — штатно
недоступное NaN после успешного такта filter2win. Отказ ядра status=1
вызывает диагностическое исключение: состояние не публикуется.
Состояние успешного такта с NaN публикуется. Статусы адаптера не являются
статусами checks. Скалярные метрики: successful, total, failure_fraction,
bias и rmse только по доступным значениям; ноль вместо пропуска запрещён.

@CRITERION TEST-FILTER-001: все 101 выход и состояния сценария сравниваются
с прямыми вызовами filter2win на тех же измерениях; NaN и мощность окна совпадают.
@CRITERION TEST-FILTER-002: штатный NaN обновляет состояние, отказ ядра
сохраняет его; scalar режим не меняет позиционные режимы и их проверки.

## Подключение сценария

filter2win_observations в matlab/tests/support генерирует только входы.
filter2win_scenario в matlab/tests/support выполняет их через движок,
сохраняя пять выходов прежнего API. Генератор графиков подключает support
явно и восстанавливает путь. Интерактивный test_twofilter использует setup_test_paths.
@CRITERION TEST-FILTER-004: на seed 1729 совпадают временная сетка, истина,
измерения, конечное rng, все выходы фильтра и мощности окна с прежней схемой
генерации и прямым циклом. Графические команды не изменяются.

## Геометрический проход

service_run_path исполняет безынерционные оцениватели на постоянной геометрии
постов и заданных наблюдениях. parameter — конечная строго возрастающая строка,
не время в секундах. Результат содержит parameter, но не time. Подключён
generate_context_test_images; графические команды и генерация входов не меняются.
@CRITERION TEST-PATH-001: на сокращённых ближнем/дальнем сценариях все четыре
метода совпадают с прямым циклом по статусам и массивам через isequaln.
@CRITERION TEST-PATH-002: отказы не дают нулевую ошибку; повтор параметра
отклоняется. Ансамблевый, временной и скалярный режимы сохраняются.

@CRITERION TEST-CONTEXT-001: полный вызов generate_context_test_images на
изолированных сокращённых конфигурациях (7 точек, 8 реализаций, оба расстояния)
создаёт 8 результатов методов и 10 читаемых PNG. Сохранённые траектории и
ансамбли совпадают с прямыми вызовами на сохранённых входах; pathResult
согласован с legacy-полями. RNG вызывающего кода восстановлен.
Это интеграционная проверка, не статистическая или визуальная приёмка комплекса.

## Допуск результатов к метрикам

@CRITERION TEST-VALID-001: result.valid допускает только status=0, конечный
выход и отсутствие contract_violations. Нарушение исключает весь кадр из
условных метрик, но не меняет исходные samples/statuses/errors.
Правило одинаково для ансамбля, траектории и скаляра. Если допустимых кадров
нет, successful=0, failure_fraction=1 и rmse=NaN. valid не является PASS check.

@CRITERION TEST-VALID-002: tis_experiment_cell использует result.valid для
поканального RMSE, максимального промаха и числа успешных реализаций;
generate_context_test_images — для числа отказов траектории и облака оценок.
На сохранённых данных число успешных и метрики согласованы с этой маской.
Другие потребители исторических MAT требуют отдельного аудита формата.

@CRITERION TEST-VALID-003: перед редукцией завершённого контекста result
проверяет double samples [D×N], double statuses [1×N] (0/1/2 либо NaN),
logical contract_violations [1×N] и cell errors [1×N]. D=1 для скаляра,
D=3 для позиции. Комплексные значения и неявное расширение масок запрещены.
Несоответствие вызывает libtr:testmodel:ResultShape до вычисления valid.
unit_test_result_validity проверяет инъекции во всех трёх режимах; штатные
NaN-статусы исключений сохраняются как диагностика и не допускаются к метрикам.

@CRITERION TEST-VALID-004: result принимает только скалярную структуру контекста
со скалярным result и обязательными полями результата. Курсор — конечный
неотрицательный целый числовой скаляр. Повреждённая оболочка отклоняется
с libtr:testmodel:Context; корректный курсор, не равный числу результатов,
с libtr:testmodel:Incomplete. Проверки выполняются до доступа к полям
и вычисления метрик. Инъекции проверяются во всех трёх режимах.

@CRITERION TEST-VALID-005: перед редукцией истина — конечный реальный double
строго 3×1 для ансамбля, 3×N для траектории или 1×N для скаляра.
Отсутствующий mode означает ансамбль; заданный mode — 'trajectory' или 'scalar'.
Траектория содержит ровно одну шкалу time/parameter; скаляр — только time.
Шкала — конечная строго возрастающая double-строка 1×N. Несоответствия
отклоняются с Context до вычисления ошибок; неявное расширение истины запрещено.
Проверка unit_test_result_validity включает повреждения и прежний path-режим.

@CRITERION TEST-VALID-006: каждая ячейка errors содержит char-строку либо
пустой char размером 0×0 или 1×0. Допускается исходный маркер отсутствия
диагностики double [] размера 0×0 из инициализатора. Остальные числа,
объекты string, вложенные контейнеры
и char-матрицы отклоняются с libtr:testmodel:ResultShape до расчёта метрик.
Текст сохраняется без изменения, включая Unicode и символы перевода строки.
Наличие текста само по себе не определяет valid или статус проверки.
