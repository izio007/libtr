Отклонённые, эквивалентные и выполненные правки удаляются.

## Автономная отладка триггера — конфликт действующих ограничений

**Было:** отсутствие runner запрещает обходные запуски; matlab/function/ — ядра.
**Стало (решение Шефа, требует согласования с действующим инженерным регламентом):**
разрешены промежуточные отладочные средства для разработки runner/сервера;
чистые ядра переносятся в matlab/engine/ с сохранением контрактов и проверками.
Первый runner уже работает без обхода запрета; дальнейшая миграция пути и
сокращение норм не объявляются выполненными этим запуском. Сохраняются три
инварианта Шефа: разделение обязанностей, тихая диагностика/явная память,
атомарная фиксация без подгонки математики и эталонов.

## GPU-распараллеливание на Code Freeze

Файл: .clinerules, раздел 3. Основание: прямое указание Шефа о разделении
текущих инкрементальных проверок и массового исполнения на Code Freeze.

**Было:** Проверяются изменённый пакет и затронутые зависимости;
полный прогон и экспорт документов по умолчанию не выполняются.

**Стало:** В локальной итерации выполняются адресные проверки изменений;
обязательное GPU-исполнение не требуется. На Code Freeze массовые численные
испытания и расчёты для отчётности исполняются пакетно и параллельно на GPU.
CPU-fallback для этих расчётов запрещён: отсутствие GPU, неподдерживаемая
операция или нехватка памяти фиксируются как препятствие, а не успешный CPU-прогон.
CPU обеспечивает диспетчеризацию, ввод-вывод, сборку, независимые контрольные
сравнения и представление результатов; это не замена GPU-расчёта.
Полный прогон не запускается автоматически при каждом изменении.
Экспорт HTML/Live Editor остаётся только по прямой команде при Release.

## Аналитическая методика тестирования

Файл: VPrincipe.md, раздел 2. Основание: команда Шефа 06.10.2026 о
верхнеуровневом Markdown-документе аналитика, независимом от ядра и
системы тестирования. Проект формата: Principes/testing_methodology.md.

**Было:** REQ-VDESIGN-002 задаёт содержание checks до реализации;
форма целевого перечня и методик как отдельного аналитического документа
не установлена.

**Стало, предложение:** методика тестирования — версионируемый
аналитический документ из целевого перечня проверяемых обязательств и
методик их проверки. Каждая цель имеет основание и условия действия;
каждая методика — данные, воздействия, наблюдаемые величины, независимый
ориентир и критерии решения. Полнота проверяется по исходному заданию и
покрытию обязательств сценариями. Документ начинается с назначения, границы проверки, целей и наглядной
программы испытаний. Итог относится к выбранным условиям и профилям.
Сценарий описывается читаемой карточкой:
вход по этапам, изменяемые настройки с соответствием конфигурации и
ожидаемый результат с допусками и сроками. Подключение к исполнителю
указывается явно. Формальная заполненность не доказывает
содержательную правильность. Документ сохраняет смысл при замене реализации
объекта и инструментов испытания. Исполнители реализуют установленную
методику без скрытой подмены требований и ожидаемых результатов.
