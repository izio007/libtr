# Задачи и решения для Шефа

Интерфейс решений — этот файл, без вопросов в диалоге. Разрешимые по контрактам
вопросы ИИ решает самостоятельно; заблокированный шаг не останавливает независимые работы.
Решения фиксируются в файле темы proposals/, разрешённые работы — в need_work.md.
Закрытые вопросы удаляются. Поправки регламентов — в need_correct.md.

## F2W-HOST-01. Новый изолированный сервер для приёмки архива

Команда Шефа: новый MATLAB-сервер без штатных путей проекта. При обследовании
02.10.2026 :5555 занят постоянным host PID 28860, старт 01.10.2026 09:37:17,
запущенным через tools/matlab/tcpserver5555.m. Процесс не изменялся.
Регламент требует единственный постоянный сервер и его сохранение.
- [ ] Разрешить контролируемую замену этого host на новый из распакованного
  пакета после проверки живой очереди и отсутствия активного задания либо
  согласовать другой режим изолированной приёмки. Второй порт не используется
  как молчаливое исключение из регламента. Отсутствие queued/running в файлах
  отчётов не является доказательством пустой живой очереди.
Текущие reset/run вызывают setup_test_paths проекта, поэтому перезапуск
существующего bootstrap не докажет автономность. Остаток — F2W-PACK-01.

## F2W-TIME-01. Временная база готовности filter2win

Основание: утверждённые MIN_WINDOW_TICKS/MIN_WINDOW_DURATION и ревью
filter2win от 02.10.2026. Формула t_current - t_oldest допускает накопление
возраста на пропусках; требование «интервал, покрытый данными» предполагает
t_newest_accepted - t_oldest_accepted. Это разные критерии готовности.
- [ ] Выбрать временную базу. Предложение исполнителя: размах времён принятых
  элементов текущего основного окна; пропуски и отбраковка не наращивают базу.
  После очистки база набирается заново, после перезахвата — по перенесённым парам.
До решения переходный режим и настройки 30/450 км не меняются. Независимый
FIFO-рефакторинг разрешён; адресный остаток — F2W-IMPL-01 в need_work.md.

## ICD-01. Исходные требования первого профиля обмена

Основание: открытые решения раздела 9 IcdPrincipe.md; работа — ICD-01
в need_work.md. Привязка к коммиту постановки — история этих файлов.

- [ ] Указать первый целевой объект/состав участников и обязательные каналы,
  платформы, ПИВ или другие исходные спецификации, если они уже определены.
- [ ] Для команд и событий определить допустимую задержку и требуемую безопасную

  требование. Правило 3T для периодических параметров повторно не согласуется.
- [ ] Указать внешние ограничения безопасности: доверенная среда или защита
  от подмены, кто вправе публиковать и активировать конфигурации, либо документ
  с этими требованиями. Конкретные механизмы предложит исполнитель.

До получения исходных требований продолжаются инвентаризация, декомпозиция
и варианты контрактов; неподтверждённые характеристики не фиксируются как нормы.
Повторное разрешение согласованных работ, Silent PASS и Defect Snapshot не нужно.
