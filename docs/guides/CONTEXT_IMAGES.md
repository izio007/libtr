# Графики интеграционных расчётов ТИС

В MATLAB из корня репозитория:

```matlab
addpath('matlab');
status = run_tests('integration');
```

В списке можно независимо выбрать `context30`, `context450`, `tis` и сквозной
`filter2win`. `context30` и `context450` выполняют ближнюю и дальнюю траектории
из `tis_trajectory_scenarios`: соответственно 500 и 300 точек. Для каждого из
четырёх методов LLS, WLLS, GN и GNP рассчитываются полная траектория и ансамбль
в её центральной точке. В текущих конфигурациях ансамбль содержит 5000 реализаций;
это полноценные расчёты и они требуют времени.

```matlab
status = run_tests('integration', {'context30'});
status = run_tests('integration', {'context450', 'tis'});
```

Каждое окно контекстного расчёта содержит истинную и оценённую траектории,
ошибку положения, облако центрального ансамбля и его эмпирические полуоси.
RMSE относится к центральному ансамблю. Отказы исключаются из условных метрик
и показываются в отчёте. Один выбранный контекст создаёт четыре окна/PNG,
оба — восемь. Unit-иллюстрации cov2std сюда не добавляются.

`tis` использует существующий `test_tis_ensemble`: пять геометрий, четыре
независимых решателя, 64 реализации в каждой опорной точке. Открываются пять
окон с облаками ошибок и эмпирическими осями. Данные сохраняются в
`tis_ensemble.mat` и `tis_ensemble.json`.

`integration_context` сохраняет выбранные конфигурации и вызывает
`generate_context_test_images`. Исходные измерения и результаты методов
записываются в MAT; `context_images.json` содержит файлы, метрики и отказы.
Численные проверки сохраняются. PASS означает отсутствие предусмотренных
отказов и нарушений контракта, а не выполнение неустановленного допуска точности.

Видимые окна и PNG используют один результат расчёта. Unit-вызовы и TCP-этап
`integration` используют те же функции с `showFigures=false`, сохраняя картинки
без открытия окон. Проверки формата картинок и вложенные unit-запуски из
генератора удалены.
