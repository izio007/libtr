# Размещение продукта и испытаний

Нормативная архитектура — .clinerules; контракт проверок — matlab/tests/matlab_layout_contract.md.

- matlab/function/ — чистые вычислительные ядра.
- matlab/engine/ — физическая модель, генерация наблюдений и выполнение ТИС без настроек конкретных испытаний.
- matlab/tests/ и support/ — сценарии, входы, реперы, метрики и испытательный исполнитель.
- tools/matlab/ — инфраструктурный вход tcpserver5555.m.
- tools/pipeline/ — постоянный host, протокол и отчёты.
- tools/docs/ — средства документов; экспорт только при выпуске по команде Шефа.

Производственный путь содержит только function/ и engine/. Продукт не вызывает tests/ или tools/.
Тестовый путь устанавливает matlab/tests/setup_test_paths.m; корень matlab/ не нужен.

Обычные задания используют существующий TCP:5555. Host очищает тестовый контекст
между заданиями. Изменение незаблокированного теста не требует перезапуска.
Инфраструктурный вход — tools/matlab/tcpserver5555.m, а не скрипт в корне.
Порядок безопасного запуска и остановки — PIPELINE.md.

unit_test_production_isolation проверяет разрешение и статическое замыкание
зависимостей; это не доказательство полноты динамических зависимостей.
Стохастические модели engine используют RNG, чистые ядра function — нет.
Явная изоляция RNG-контекстов остаётся отдельной задачей.
Перемещение не исправляет математические ограничения реперов и моделей.
