# Предложения шефу: договор трансляции математических паспортов

Статус: ответы на три вопроса утверждены шефом и внесены в действующие регламенты. Остальные пункты ниже сохраняются как история предложения.

## Дополнение PaeroPrincipe.md

1. Единственный первоисточник паспорта — `docs/<модуль>_theory.txt` в UTF-8, Markdown + LaTeX. HTML и Live Editor — производные; ручные содержательные исправления в них запрещены.
2. Математические выражения в тексте, заголовках, списках и таблицах обязательно заключаются в `$...$` или `$$...$$`. Исполняемый синтаксис оформляется как код, а не выдается за формулу. Транслятор не угадывает границы математических выражений.
3. Графики задаются отдельными маркерами `[image: имя.png]`; изображения получают воспроизводимым расчетом MATLAB в runtime. Псевдографика запрещена.
4. Приемка требует проверок исходной разметки, регрессионных тестов, проверки формульного движка HTML и экспорта Live Editor. Успешная проверка синтаксиса MATLAB не доказывает правильность отображения.
5. Подтверждение визуального качества должно указывать проверенные документы и артефакты. Нельзя объявлять весь пакет визуально проверенным по одному документу.

## Дополнение PlainTextPrincipe.md

1. Экранирование выполняется один раз, отдельно для каждого целевого формата. Обратные слеши HTML не удваиваются по правилам Live Editor.
2. Формулы заголовков выводятся через `%[text]`, а не через служебный заголовок `%%`. Содержательное дублирование заголовков исключается.
3. LaTeX-команды вне математических разделителей и вне явно оформленного кода — ошибка сборки с указанием первоисточника. Непарные разделители также блокируют сборку.
4. Поддержка LaTeX определяется пересечением возможностей целевых движков. Эквивалентные адаптации фиксируются в трансляторе и тестах: например, `\operatorname{rcond}` → `\mathrm{rcond}` для Live Editor. Неподдерживаемые команды нельзя молча оставлять в документе.
5. HTML должен проходить проверку после завершения MathJax: отсутствие ошибок формул, совпадение числа отрисованных формул с исходником, доступность изображений. Live Editor проверяется экспортом и просмотром контрольных страниц, включая заголовки, списки, индексы и матрицы.

## Утвержденные решения

- Закрепить базовый набор: \sum, \prod, \alpha, \beta, \mathbf, \frac, \sqrt. Дополнительные команды необходимо явно учесть и проверить; полный расширенный профиль пока не утвержден.
- Сплошная постраничная визуальная приемка не требуется. Автоматические проверки выполняются для всего пакета, визуальный аудит — по утвержденным 2–3 контрольным страницам. Конкретный набор страниц пока не выбран.
- Обязательно сохранять двумерную форму bmatrix в Live Editor. Линеаризация матриц запрещена.

## Разрыв между регламентом и реализацией

На момент фиксации решений translate_docs.py еще линеаризует bmatrix. Это несоответствие требует отдельной доработки с проверкой экспорта; изменение регламента не является подтверждением исправления транслятора. Также требуется реализовать проверку разрешенного профиля команд и закрепить конкретные контрольные страницы.
