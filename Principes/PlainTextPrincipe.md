# Текст и преобразование документов

Математический текст редактируется в Markdown. HTML, PDF и Live Editor
создаются, когда конкретной задаче нужен соответствующий файл.
Перевод выполняет один скрипт с явным входом и выходом.

## Исходник

- Используй обычный Markdown: заголовки, абзацы, списки, таблицы и блоки кода.
- Для совместного просмотра в GitHub и VS Code записывай блочные формулы в
  ограждённых блоках с языком `math`, строчные — как `$` + обратная кавычка +
  LaTeX + обратная кавычка + `$`. Это защищает символы формулы от Markdown.
  Используй обычное LaTeX-экранирование. В блоке `math` дополнительные `$$` не нужны.
- GitHub блокирует `\operatorname`, даже если KaTeX локально принимает формулу.
  Для именованного оператора используй `\mathop{\mathrm{rcond}}\nolimits`;
  для индекса под оператором — `\limits`. После команды перед буквенным символом
  оставляй разделитель: `\nolimits P`, а не `\nolimitsP`.
- Матрицы и кусочные выражения сохраняй в двумерной форме (`bmatrix`, `cases`).
- Изображения связывай с имеющимися файлами обычной записью Markdown
  `![Описание](относительный/путь.png)`. Для просмотра на GitHub файл должен быть
  доступен в репозитории либо по указанному внешнему адресу. Служебная запись
  `[image: имя.png]` поддерживается экспортом и не отрисовывается на GitHub.
- Для схем используй блоки `mermaid`, если они помогают показать порядок или
  ветвление. Для расчётного графика укажи смысл кривых, единицы и происхождение
  данных. Не подменяй отсутствующий результат расчёта выдуманным изображением.
- Код, имена функций, числа, единицы и математический смысл при переводе сохраняются.

При исправлении отображения проверяй целевое представление. Распознавание формул
Markdown API и локальный KaTeX не доказывают отсутствие запретов макросов на GitHub:
на опубликованной странице дождись завершения рендеринга и проверь ошибки.

## Скрипт преобразования

Экранирование HTML и синтаксис Live Editor — внутреннее дело скрипта.
Не размечай Markdown заранее под служебные `%[text]` и не удваивай в нём
слеши ради MATLAB. Специфика формата не должна превращаться в ручную работу
по каждому документу или в самостоятельный нормативный профиль.

Экспорт запускается отдельно и использует уже рассчитанные изображения.
Он не входит в обычные тесты и упаковку. Для переводчиков не нужны тесты,
отдельные валидаторы, паспорта, контрольные листы и процедура приёмки.
Если запрошенный файл отображается неверно, исправь конкретную ошибку
в скрипте и получи результат. Повторяй расчёт только при изменении его данных
или кода, а не ради нового формата. После получения нужного файла остановись.
