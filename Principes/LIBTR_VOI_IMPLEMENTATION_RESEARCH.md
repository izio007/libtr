## 2. Применение и восстановление

Требуется Python 3 со стандартной библиотекой. В примерах имя интерпретатора — `python3`; в среде, где он доступен как `python` или `py -3`, следует использовать соответствующую команду.

### 2.1. Просмотр

```bash
python3 apply_libtr_voi_research.py --root "/path/to/libtr" --check
python3 apply_libtr_voi_research.py --root "/path/to/libtr" --check --diff
```

Оба вызова выполняют только чтение. Без выбора действия используется тот же режим проверки.

### 2.2. Запись

```bash
python3 apply_libtr_voi_research.py --root "/path/to/libtr" --apply
```

До первой замены проверяются все целевые файлы. Для существующего конспекта допустимы точная версия исходного коммита, точная редакция текущего `main` с Git blob `717df6...`, прежняя 11-файловая редакция установщика или уже установленный результат; для новых функций и тестов — отсутствие файла либо уже установленный результат. Неизвестное содержимое останавливает применение целиком.

Исходный документ имеет SHA-256:

```text
5fee0f1ff1403ff8afe6bcb1aca6b7c8ced379526e274b786de4f836267eb3a4
```

Проверка допускает LF и чистый CRLF, сохраняя стиль существующего файла. Смешанные окончания строк, BOM и содержательные изменения не удаляются нормализацией. На POSIX сохраняются исходные права, включая режим `755` существующего документа. В Windows сопоставляется доступный признак чтения/записи; Unix-биты исполнимости не объявляются поддерживаемыми.

Установщик принимает как исходный конспект указанного коммита, так и **точный конспект из прежнего `apply_libtr_voi_research.py`**. Содержательные ручные правки ни одной из версий не перезаписываются. Дополнительные исследовательские файлы создаются только при отсутствии либо при точном совпадении с их собственным содержимым.

Все исходные байты и план замены сохраняются под:

```text

```

Точный путь печатается при применении. Запись каждого файла выполняется через временный файл и `os.replace`. Весь набор файлов не является одной транзакцией файловой системы.

При обычном исключении или `KeyboardInterrupt` установщик пытается восстановить собственные изменения. Если файл уже изменён другим процессом, его новое содержимое не затирается откатом. После необрабатываемого завершения процесса можно использовать сохранённый план восстановления.

Повторный `--apply` для уже установленного результата не меняет файлы и не создаёт новую резервную копию.

## 3. Декомпозиция по правилам проекта

Декомпозиция следует [PaeroPrincipe.md](https://github.com/izio007/libtr/blob/5f85efab2149f37b17dc4e3d50a324f4ff3ed6d7/Principes/PaeroPrincipe.md): состояние передаётся явно, вычислительное ядро не управляет файлами и запуском среды, локальный кандидат не считается принятым до выбора и исполнения действия.

Один такт оценщика имеет порядок:

1. `voi_step` проверяет конфигурацию, время, форму входа и согласованность сохранённого контекста.
2. `voi_conditions` читает один снимок, строит допустимый луч, локальную копию кольцевого буфера, априорный и МНК-кандидаты.
3. `voi_transition` выбирает единственное действие по уже вычисленным признакам.
4. `voi_execute` принимает допустимую запись и выбранную модель, вычисляет статус и возраст, затем возвращает согласованные состояние и выход.

Математические операции вынесены в самостоятельные функции, потому что у них есть отдельные входы, область применимости и независимые эталоны. Сигнал непрерывной коррекции имеет собственный контекст: его гладкость не следует из наблюдаемости дальности.

[VPrincipe.md](https://github.com/izio007/libtr/blob/5f85efab2149f37b17dc4e3d50a324f4ff3ed6d7/Principes/VPrincipe.md) применяется на трёх уровнях:

| Уровень | Проверяемое требование | Независимое основание |
|---|---|---|
| Компонент | Угловое преобразование, МНК, кубические участки | Аналитические векторы, известная пространственная точка, рациональные значения полиномов |
| Взаимодействие | T/F/U, накопление лучей, приоритет действия, сохранение при отказе | Явно заданные последовательности событий и ожидаемые состояния |
| Конвейер | Первый выход, круг и спираль, задержка, ограниченный буфер, финал | Известная неподвижная цель и вычисленные из неё наблюдения |

В конспекте сохранена связь с прежними обозначениями F01–F17; F18–F21 относятся к геометрии и коррекции, а F22–F26 — к подготовке измерений, условной инвариантности, ковариации и происхождению данных. Отдельный DSL, сервис или обязательный реестр требований не вводится.

## 4. Математические изменения

### 4.1. Правильный смысл углов

Входные \(a,b\) — знаковые углы к плоскостям \(xz\) и \(xy\) приёмника:

\[
u_{R,y}=\sin a,\qquad
u_{R,z}=\sin b,\qquad
d=1-\sin^2a-\sin^2b,\qquad
u_{R,x}=+\sqrt d.
\]

Выбрана открытая передняя полусфера. В коде допускается \(d>32\varepsilon_{\mathrm{mach}}\); полоса округления около нуля получает статус BOUNDARY. Достоверно отрицательное \(d\) отвергается. Неизвестная полусфера должна быть разрешена до вызова этого одногипотезного интерфейса.

При \(-30^\circ/-30^\circ\) правильное направление:

\[
\mathbf u_R=(1/\sqrt2,-1/2,-1/2)^\mathsf T.
\]

Его азимут равен \(-35.2643896828^\circ\), угол места — \(-30^\circ\). Ошибочная сферическая подстановка даёт \((3/4,-\sqrt3/4,-1/2)\) с нормой ровно 1, но обратный первый угол равен \(-25.6589062733^\circ\).

### 4.2. Привязка каждого луча

\[
\mathbf u_i=C_i\mathbf u_{R,i},\qquad
\mathbf X=\mathbf o_i+\rho_i\mathbf u_i,\qquad \rho_i>0.
\]

Матрица \(C_i\) переводит компоненты из системы приёмника в общую систему. Начало \(\mathbf o_i\) и матрица относятся к \(t_{\mathrm{obs},i}\). Использование текущей привязки для задержанного кадра изменило бы исходный луч.

Этого представления достаточно для кривой траектории наблюдателя. Векторный расчёт также не зависит от разрыва шкалы азимута на \(0/360^\circ\).

### 4.3. База по сохранённой истории

\[
L=\max_{i,j}\|\mathbf o_i-\mathbf o_j\|_2.
\]

При возвращении к началу круга текущая точка совпадает с исходной, но сохранённая база может оставаться равной диаметру круга. В проверке окружности она равна 600 м.

Большая база сама по себе не гарантирует засечку: коллинеарные перемещения вдоль линии визирования могут оставить все направления параллельными. Поэтому \(L>L_{\min}\) является одним из условий, а не единственным разрешением обновления.

### 4.4. МНК без обращения нормальной матрицы

\[
P_i=I-\mathbf u_i\mathbf u_i^\mathsf T,\qquad
J(\mathbf X)=\sum_i\|P_i(\mathbf X-\mathbf o_i)\|_2^2.
\]

Нормальные уравнения:

\[
A\widehat{\mathbf X}=\mathbf c,\qquad
A=\sum_iP_i,\qquad
\mathbf c=\sum_iP_i\mathbf o_i.
\]

Вычислительное решение использует центрированные координаты и прямоугольную систему \(H\boldsymbol\xi\approx\mathbf y\). Вызывается явное экономное QR:

```matlab
[Q,R] = qr(H,0);
xi = R \ (Q' * rhs);
```

SVD используется для диагностики численного ранга и

\[
\kappa_2(A)=
\left(\frac{\sigma_{\max}(H)}{\sigma_{\min}(H)}\right)^2.
\]

Принятие требует конечного результата, \(L>L_{\min}\), численного ранга 3, строгого \(\kappa_2(A)<\kappa_{\max}\), всех положительных направленных дальностей и допустимой RMS-невязки. Равенство пределу обусловленности отвергается.

МНК проекторов минимизирует расстояния до содержащих лучи прямых. Проверка \(\rho_i>0\) дополнительно исключает решение позади начала хотя бы одного сохранённого луча. Неудачная засечка сохраняет прежнюю принятую точку; пригодный новый луч при этом может накопиться для последующих тактов.

Нормировка применяется только к допустимой ошибке представления единичного вектора, не более \(10^{-10}\). Она не исправляет несовместимые углы. Это предотвращает ложный ранг проекторов почти единичных параллельных направлений.

### 4.5. Первый такт

\[
\mathbf p_0=\mathbf o_0+R_0\mathbf u_0.
\]

Уже при \(L=0\) публикуются конечная точка и коэффициенты

\[
S_0(\tau)=\mathbf p_0+0\tau+0\tau^2+0\tau^3.
\]

Априорная дальность не добавляется в МНК как независимое измерение. Один луч по-прежнему не наблюдает дальность. Первый выход требует допустимого первого луча, его привязки, конечной априорной суммы и положительного представимого смещения вдоль луча; при отсутствии этих данных возвращается UNAVAILABLE. Если при большой абсолютной координате сумма округлилась точно в начало луча, такой приор не публикуется.

## 5. Стационарная модель и непрерывная коррекция

### 5.1. Два разных математических объекта

`voi_step` выдаёт оценку неподвижной цели \(\mathbf p_k\) и её модель:

\[
S_k(\tau)\equiv\mathbf p_k.
\]

Каждая такая версия принадлежит классу кубических сплайнов степени не выше трёх, гладка и удовлетворяет условиям Клэмпа. Замена \(\mathbf p_k\) между тактами сама по себе создаёт скачок выдаваемой точки.

Поэтому добавлен отдельный сигнал \(\widetilde S(t)\). Он плавно приближается к принятой точке и не обозначает движение цели. Его значения, первая и вторая производные совпадают по обе стороны каждого стыка и момента перепланирования.

### 5.2. Три кубических участка

Пусть \(H>0\) — заданная длительность перехода. При новой точке из прежнего сигнала вычисляются текущие \(\mathbf r,\mathbf v,\mathbf a\). Новое продолжение начинается с этих трёх величин и через \(H\) достигает новой точки с нулевыми первой и второй производными.

У одного кубика четыре коэффициента на координату, а граничных условий шесть. Три участка при заданных внутренних временах дают необходимые шесть степеней свободы после условий \(C^2\)-склейки.

Коэффициенты хранятся как локальные смещения от `position_origin` в нормированном времени каждого участка. Из-за округления абсолютных времён соседние интервалы могут немного различаться; в решении используются их фактически представимые длины.

При \(H=3\), переходе \(0\to6\) и исходном покое по одной координате:

| Время | Значение | Первая производная | Вторая производная |
|---|---|---|---|
| 0 | 0 | 0 | 0 |
| 1 | 1 | 3 | 6 |
| 1.5 | 3 | 4.5 | 0 |
| 2 | 5 | 3 | -6 |
| 3 | 6 | 0 | 0 |

При перепланировании производные сохраняются. `target=[]` продолжает прежний переход; точное повторение прежней конечной точки не отодвигает срок завершения. После конца сигнал постоянен.

Перед принятием и при чтении проверяются невязки обоих стыков и конечных условий. Их допуск зависит от локального перемещения. Большая глобальная координата не разрешает большой локальный разрыв.

### 5.3. Что происходит в 240 с

На первом вызове в момент 240 с или позднее сначала обрабатывается последний допустимый кадр с `t_obs<=240`, затем фиксируется оценка:

- FINAL_C2_SPLINE — имеется ранее или сейчас принятая МНК-модель.
- FINAL_APRIORI — сохранилась только гипотеза по \(R_0\).
- FINAL_UNAVAILABLE — конечная модель не была получена.

Стационарная модель удовлетворяет \(S'(0)=S'(240)=0\). Если последний кадр впервые изменил точку в 240 с, непрерывный сигнал достигает её в \(240+H\). Одновременно мгновенно попасть в новую точку и сохранить непрерывность в 240 с невозможно.

При позднем завершающем вызове используется его фактическое время: например, вызов в 250 с и \(H=12\) может завершить новую коррекцию в 262 с. Поля `finalized_at` и `correction_end` поэтому имеют разные значения.

## 6. Программный интерфейс

### 6.1. Конфигурация оценщика

```matlab
cfg = struct('R0',800, 'Lmin',50, 'kappa_max',1e4, ...
             'capacity',32, 'time_start',0, 'time_end',240, ...
             'age_max',60, 'residual_max',Inf);
estimate_ctx = struct();
correction_ctx = struct();
H = 12;
```

Это параметры демонстрационного сценария, а не универсальные нормативы.

| Поле | Смысл и область |
|---|---|
| `R0` | Положительная гипотетическая дальность, м |
| `Lmin` | Неотрицательный порог базы, м |
| `kappa_max` | Конечный параметр \(\kappa_{\max}>1\), верхняя граница принятия строгая |
| `capacity` | Целое число записей не меньше 2 |
| `time_start`, `time_end` | Конечные секунды, конец больше начала; разность должна быть конечной |
| `age_max` | Неотрицательный предел возраста, с; по умолчанию \(+\infty\) |
| `residual_max` | Неотрицательный предел RMS поперечных расстояний, м; по умолчанию \(+\infty\) |

Все числовые поля конфигурации — вещественные double. Изменение конфигурации требует нового пустого контекста.

### 6.2. Наблюдение

```matlab
obs = struct('m',1, 't_obs',0, ...
             'a',-pi/6, 'b',-pi/6, ...
             'origin',zeros(3,1), 'C',eye(3), 'nav_status',1);
```

`origin` имеет размер \(3\times1\), `C` — \(3\times3\). Углы в радианах. `C` должна быть собственной ортогональной матрицей; отражение с определителем -1 отвергается.

`nav_status=1` означает доступную привязку, `0` — известную непригодность, `-1` или отсутствие поля — отсутствие сведений. При объявленной доступности отсутствующие или некорректные координаты являются ошибкой F.

При пропуске достаточно:

```matlab
obs = struct('m',0);
```

Остальные поля тогда не читаются. Нулевые углы \(a=b=0\) допустимы и не означают пропуск.

### 6.3. Согласованное применение двух контекстов

```matlab
[rc, next_estimate, estimate, debug] = ...
    voi_step(cfg, estimate_ctx, current_time, obs);
if rc ~= 0
    error('voi:EstimateAPI', '%s', estimate.reason);
end

target = [];
if debug.model_updated
    target = estimate.point;
end
[sc, next_correction, signal] = ...
    voi_correction_step(H, correction_ctx, current_time, target);
if sc ~= 0
    error('voi:CorrectionAPI', '%s', signal.reason);
end

estimate_ctx = next_estimate;
correction_ctx = next_correction;
% Только здесь публикуются estimate и signal для данного составного шага.
```

Оба контекста принимаются после успешного вычисления обоих кандидатов. При ошибке любого вызова ранее опубликованные контексты остаются прежними.

В `voi_step` `rc=0` означает завершённый такт, включая пропуск и удержание. Это не равнозначно новому успешному МНК. Для этого служит `debug.model_updated` вместе с `estimate.basis`.

Основные поля результата:

| Поле | Значение |
|---|---|
| `estimate.available` | Имеется конечная модель |
| `estimate.observed` | Основание модели — принятая МНК-засечка |
| `estimate.basis` | 0 — NONE, 1 — PRIOR, 2 — LS |
| `estimate.phase` | Фаза 1–4 |
| `estimate.point` | Принятая точка в общей системе |
| `estimate.coeff` | \(3\times4\): коэффициенты стационарной модели по обычному времени |
| `estimate.age`, `estimate.fresh` | Возраст опорных данных и сравнение с `age_max` |
| `debug.geometry_state` | Условие новой засечки данного такта: 1, 0 или -1 |
| `signal.position` | Текущая точка непрерывного сигнала |
| `signal.velocity`, `signal.acceleration` | Его первая и вторая производные |
| `signal.coeff` | \(3\times4\times3\): локальные нормированные коэффициенты трёх участков |
| `signal.position_origin` | Общий координатный сдвиг для этих коэффициентов |
| `signal.time_origin`, `signal.time_scale` | Начало и длительность каждого участка |
| `signal.correction_end` | Время окончания текущего перехода |

`signal.coeff` нельзя передавать в `voi_spline_eval` как обычные коэффициенты по секундам. Для чтения всей кусочной функции используется:

```matlab
[rc, signal_at_query] = voi_correction_eval(correction_ctx, query_time);
```

При постоянном начальном сигнале узлы совпадают и масштабы времени равны нулю; evaluator обрабатывает его отдельной ветвью без деления. После смены плана сохраняется только текущий план; запрос времени до его начала отклоняется.

### 6.4. Время, буфер и возраст

Активные такты оценщика и шаги коррекции требуют строго возрастающего текущего времени. Зафиксированную модель оценщика можно читать на времени не раньше последнего такта без изменения контекста. Для повторного чтения коррекции без продвижения шага служит `voi_correction_eval`.

Задержанные и поступившие не по времени наблюдения допускаются при их исторической привязке. Точное повторение `t_obs` в сохранённом буфере отклоняется. Буфер вытесняет записи по порядку поступления, поэтому при задержках это не обязательно самые старые времена наблюдения. Уникальность доставки за пределами ограниченного буфера обеспечивает источник.

Для модели хранится `support_time` — время первого приора либо максимальное время наблюдения в последнем принятом МНК. Последнее принятое в буфер наблюдение хранится отдельно. Запись, не давшая новой засечки, не освежает старую модель.

При `support_time=180` и текущем времени 240 возраст равен 60 с. Для неподвижной цели это само по себе не делает исторические лучи неверными. `fresh` — признак принятой политики возраста; он не является оценкой точности.

## 7. Демонстрация на пространственной спирали

Код выполняется из корня libtr после установки. Наблюдения формируются непосредственно из заранее известной неподвижной точки. Путь наблюдателя неплоский, матрица поворота меняется, два такта пропускаются.

```matlab
addpath('matlab/function');
cfg = struct('R0',800,'Lmin',50,'kappa_max',1e4, ...
             'capacity',32,'time_start',0,'time_end',240, ...
             'age_max',60,'residual_max',Inf);
estimate_ctx = struct();
correction_ctx = struct();
H = 12;
truth = [1500;-300;200];

for current_time = 0:10:240
    theta = 2*pi*current_time/240;
    origin = [300*cos(theta);300*sin(theta);0.25*current_time];
    yaw = 0.2*sin(theta);
    C = [cos(yaw),-sin(yaw),0; sin(yaw),cos(yaw),0; 0,0,1];
    v = truth-origin;
    u_receiver = C'*(v/norm(v));
    assert(u_receiver(1)>0);
    obs = struct('m',1,'t_obs',current_time, ...
                 'a',asin(u_receiver(2)),'b',asin(u_receiver(3)), ...
                 'origin',origin,'C',C,'nav_status',1);
    if current_time==80 || current_time==140
        obs = struct('m',0);
    end

    [rc,next_estimate,estimate,debug] = ...
        voi_step(cfg,estimate_ctx,current_time,obs);
    assert(rc==0);
    target = [];
    if debug.model_updated
        target = estimate.point;
    end
    [sc,next_correction,signal] = ...
        voi_correction_step(H,correction_ctx,current_time,target);
    assert(sc==0 && signal.ready);
    estimate_ctx = next_estimate;
    correction_ctx = next_correction;
end

assert(estimate.phase==4 && estimate.observed);
[sc,correction_ctx,signal] = ...
    voi_correction_step(H,correction_ctx,252,[]);
assert(sc==0 && ~signal.transitioning);
fprintf('Estimate error: %.12g m\n', norm(estimate.point-truth));
fprintf('Final correction error: %.12g m\n', norm(signal.position-truth));
```

Здесь последняя оценка фиксируется в 240 с. Чтение в 252 с даёт достаточное время для последнего перехода при \(H=12\). Параметры примера обеспечивают пригодную геометрию; другая траектория должна проходить те же численные проверки, а не наследовать успешный статус примера.

## 9. Границы результата

Алгоритм обрабатывает одну неподвижную цель. Произвольное движение самой цели требует другой параметризации и исследования наблюдаемости. Изменение оценок от такта к такту не является таким исследованием.

Неизвестная полусфера, неизвестная принадлежность лучей одной цели и отсутствующая историческая координатная привязка не восстанавливаются из двух чисел \(a,b\). Входной контракт должен предоставлять эти сведения.

Равные геометрические веса — выбранный квадратичный критерий. Без модели ошибок результату не приписываются несмещённость, вероятностная достоверность или ковариация.

Гладкая коррекция обеспечивает \(C^2\) и достижение принятой конечной точки, но не задаёт ограничений производных и не гарантирует отсутствие выбросов при произвольных обновлениях. \(H\) должен задаваться явно в соответствии с назначением числового потребителя.

Количество лучей ограничено `capacity`. При каждом новом луче QR и SVD работают с матрицей из трёх столбцов; прямой расчёт максимальной попарной базы требует \(O(n^2)\) операций. Объём памяти пропорционален \(n\). Оценка быстродействия конкретной среды отдельно не подменяется результатом математических тестов.

Центрирование уменьшает влияние общего координатного смещения, но не возвращает разряды, потерянные при записи входа в double. Проверяются представимые числа и полученный из них выход.

### 11.2. Математический интерфейс подготовителя

```matlab
% Фактические неравномерные времена: n x 1, с.
tobs = [0; 0.2; 0.65; 1.1; 2.2];
F = [ones(5,1), tobs];  % Столбцы (1,t) полезной зависимости.
G = [1;-1;1;-1;1];    % Пример ИЗВЕСТНОГО мешающего базиса.
y = F*[0.1;0.03] + 0.02*G;
Sigma = eye(5)*1e-4; % Только условный пример ЗАДАННОЙ ковариации.
L = [1,0; 0.5,1];     % Значение при t*=0.5 и первая производная.
[rc, prepared] = voi_oino_linear(tobs,y,F,G,Sigma,L,1e8);
assert(rc==0);
% Для точной принятой линейной модели: prepared.estimate = [0.115;0.03].
```

Стадия вычисляет линейные функционалы числовых угловых данных. Выход содержит `available`, `reason`, `weights`, `covariance`, `condition`, `constraint_residual`, `estimate`. Оператор допускает несколько функционалов за один вызов и межканальную корреляцию при объединении каналов в общий `y`. Внутри одно окно; коэффициенты `F` и `G` формирует вызывающий код на фактических отметках времени. Вариант с неизвестной структурой помехи, адаптивным выбором окна, совместным GLS и неизвестной ковариацией **в этом изменении не реализован**.

Оценка существует при известной положительно определённой `Sigma`, достаточном ранге и хорошем числе обусловленности отбеленной объединённой системы. Проверяемые тождества `F^T W=L`, `G^T W=0`, `Cov(estimate)=W^T Sigma W` следуют из конструкции в принятом конечномерном классе. Для перекрывающихся окон необходима *межоконная* ковариация `W_A^T Sigma_AB W_B`, которой простая выдача `prepared.covariance` не заменяет.

### 11.3. Текущая интеграционная граница

**Не менять** штатный вход `voi_step`, передавая ему ковариацию как будто тот её учитывает. `voi_step` по-прежнему выполняет невзвешенную проекторную засечку. Если отдельно подготовлены углы, их подстановка как `obs.a`, `obs.b` допустима лишь как передача **значений** при согласованном `obs.t_obs`, `obs.origin`, `obs.C`; это не доказывает статистическую оптимальность координат, особенно при повторном использовании исходных окон. Гарантированный первый сплайн по `R0` остаётся априорным и не получает искусственной доверительной области.

Для конечного статистического комплексирования нужны исходные ID наблюдений, межоконная ковариация и модель ошибок координат и ориентации наблюдателя. Сначала необходимо выбрать критерий и получить пространственный якобиан; нельзя объявить GLS выполненным только добавлением `Sigma` в запись измерения. Специально оставлены за границей: оценивание движущейся цели, неизвестная структура помехи, статистическая селекция каналов, идентификация неизвестной ковариации, итерационное комплексирование и вероятности достоверности.

### 11.5. Строгое отличие движения цели от движения наблюдателя

Внесённый алгоритм допускает произвольную кривую **наблюдателя** и фиксированную пространственную точку **цели**. Это не алгоритм сопровождения произвольно движущейся цели. Для второго режима §6.9 конспекта задаёт пространственно-временной базис `X(t)=sum(phi_j(t)*c_j)` и блоки `H_i=[phi_j(t_i)*P_i]`; затем необходимо независимо проверить полный столбцовый ранг, устойчивость и допустимость выбранного базиса. Статический clamped-профиль на 240 с не переносится на подвижную цель без новой внешней предпосылки.
