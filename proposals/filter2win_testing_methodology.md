# filter2win: что подаём и что хотим увидеть

Это рабочее описание интеграционных сценариев. Редактировать нужно карточку выбранного сценария: историю входа, настройки фильтра и ожидаемое поведение. Сценарий проверяет всю последовательность работы функции, включая накопление, переключения, обрыв и восстановление.

Числа существующей конфигурации приведены как текущие настройки, а не как согласованные требования. Расчёт и MATLAB при подготовке документа не запускались.

## Основной сценарий — ваш контрольный рисунок

**Название:** «Помеховая полка → обрыв → новое сопровождение → возврат».

**Что проверяем:** [исходный рисунок](filter2win_user_reference.png). Зелёная линия показывает желаемое поведение; зачёркнутые участки синей линии недопустимы.

**Начало опыта:** пустая память фильтра. Входы содержат реальные времена наблюдений; интервалы между ними могут различаться. Значения уровней и времена событий выбираются для опыта и не встраиваются в алгоритм.

| Этап | Что поступает на вход | Что хотим увидеть на выходе |
|---|---|---|
| 1. Накопление | Неровные измерения около исходного уровня | Пока базы недостаточно, результат недоступен. После выполнения условий накопления — сопровождение этого уровня. |
| 2. Одиночная помеха | Один далёкий замер, затем прежние измерения | Помеха не переносит основную полку. Выход сохраняет допустимое сопровождение прежнего уровня. |
| 3. Первая верхняя полка | Серия измерений на другом уровне | На этом участке вашего рисунка выход остаётся около прежнего уровня. Скачок на верхнюю синюю полку запрещён. Причину отказа нужно задать наблюдаемым условием, а не меткой «ложная полка». |
| 4. Обрыв | Новых измерений нет; время продолжает идти | Сначала выбранная пролонгация, затем недоступный выход. После таймаута — полный сброс памяти. |
| 5. Новые данные | Неровные измерения около нового уровня | После сброса — новое накопление. Затем сопровождение нового уровня, без использования старой базы. |
| 6. Возврат вниз | Измерения возвращаются на нижний уровень | Реакция быстрее зачёркнутого синего хвоста и спуска. Начало реакции привязано к доступному наблюдению, длительность — к выбранной политике. |
| 7. Продолжение | Измерения около нижнего уровня с шумом | Устойчивое сопровождение нижнего уровня. |

### Что меняется в этом опыте

Заполните эту таблицу при выборе конкретного опыта. Можно указать файл готовых наблюдений вместо описания генерации. Для воспроизводимости нужны сами времена и измерения либо полностью заданный способ генерации.

| Входной параметр | Значение для выбранного опыта |
|---|---|
| Исходный, верхний и конечный уровни | Указать значения или диапазоны; номиналы свободные |
| Времена начала и окончания этапов | Указать относительно начала опыта |
| Времена наблюдений | Указать список или закон нерегулярной сетки |
| Шум на каждом этапе | Указать распределение, разброс и ограничения |
| Одиночные помехи | Указать время и величину |
| Обрыв | Указать начало и длительность |
| Почему первая полка должна быть отвергнута | Указать измеряемый признак и выбранную настройку отказа |
| Почему следующая полка допустима | Указать выполняемые условия принятия |

**Пока не задано:** точный численный вход вашего рисунка, наблюдаемый признак отказа первой полки, допустимые ошибки выхода и сроки реакции. Поэтому эта карточка описывает нужный опыт, но ещё не является готовым численным тестом. Долгая полка сама по себе не разрешает заменить ожидаемый отказ захватом.

## Настройки этого сценария и реальные поля конфигурации

Исходный файл настроек: [filter2win_config.json](../matlab/tests/configs/filter2win_config.json).
Для конкретного опыта выбирается этот файл с явно перечисленными изменениями. Перечень изменений входит в карточку сценария; скрытые изменения в испытательном коде недопустимы.

### Накопление и контроль полки

| Что хотите настроить | Поле конфигурации | Сейчас в файле |
|---|---|---|
| Минимум реальных замеров основной базы | `main.min_samples` | 6 |
| Минимальный интервал между первым и последним замером основной базы, с | `main.min_span_seconds` | 3 |
| Глубина основной истории, с | `main.history_seconds` | 90 |
| Допустимый разрыв основной базы, с | `main.max_gap_seconds` | 30 |
| Свежесть основной базы, с | `main.freshness_seconds` | null |
| Модель уровня или движения | `main.model`, `main.known_velocity` | constant, 0 |
| Окрестность основной полки ниже/выше модели | `main.band.lower_margin`, `upper_margin` | 1, 1 |
| Границы выхода из окрестности ниже/выше | `main.band.exit_lower_margin`, `exit_upper_margin` | 2, 2 |
| Расширение по разбросу и нижняя граница разброса | `main.band.mad_multiplier`, `mad_floor` | 3, 0.1 |
| Рост окрестности со временем | `main.band.growth_per_second` | 0 |
| Пределы разброса, диапазона, скорости и радиуса | `main.band.max_mad`, `max_trimmed_range`, `max_abs_velocity`, `max_adaptive_radius` | 3, 6, null, null |

Поля `upper_margin` и остальные краткие имена в строке относятся к тому же префиксу, что первое поле. Аналогичные поля `alt.band.*` задают окрестность и качество второй полки отдельно от основной.

### Принятие или отказ второй полки

| Что хотите настроить | Поле конфигурации | Сейчас в файле |
|---|---|---|
| Минимум замеров кандидата | `alt.min_samples` | 6 |
| Минимальная длительность базы кандидата, с | `alt.min_span_seconds` | 0 |
| Время подтверждения кандидата, с | `alt.confirm_seconds` | 12 |
| История, допустимый разрыв и свежесть кандидата, с | `alt.history_seconds`, `max_gap_seconds`, `freshness_seconds` | 90, 15, 20 |
| Способ совместимости новых точек | `alt.compatibility.method` | median_band |
| Окрестность соседей и её рост | `alt.compatibility.neighbor_radius`, `neighbor_growth_per_second` | 2, 0 |
| Требование относительной кучности | `alt.relative_mad_ratio` | null |
| Разрешить переход по неполному окну | `alt.allow_partial` | false |
| Минимум замеров, длительность базы и подтверждение неполного окна | `alt.partial_min_samples`, `partial_min_span_seconds`, `partial_confirm_seconds` | 3, 0, 12 |
| Что делать при отказе по качеству | `alt.on_reject` | retain |
| Что делать с несовместимой серией | `alt.on_incompatible` | ignore |
| Подтверждение несовместимой серии: замеры и время | `alt.incompatible_min_samples`, `incompatible_min_seconds` | 3, 0 |
| Что делать при разрыве кандидата | `alt.gap_action` | restart |

`null` нельзя понимать как нулевое время или нулевой порог. Его смысл определяется контрактом соответствующего поля. MAD — мера разброса; это не дисперсия из приведённого в обсуждении примера. Их численные пороги не взаимозаменяемы.

### Пролонгация, обрыв и форма переключения

| Что хотите настроить | Поле конфигурации | Сейчас в файле |
|---|---|---|
| Пролонгация при отклонении измерений, с | `flow.outlier_hold_seconds` | 30 |
| Пролонгация при отсутствии данных, с | `flow.gap_hold_seconds` | 20 |
| Таймаут очистки памяти, с | `flow.timeout_seconds` | 50 |
| От какого события считать эти интервалы | `flow.outlier_clock`, `gap_clock` | first_deviation, last_input |
| Ожидание переключения, с | `handover.wait_seconds` | 0 |
| Длительность перехода, с | `handover.duration_seconds` | 12 |
| Форма перехода | `handover.curve` | smoothstep |
| Отмена при возврате к основной полке | `handover.cancel_on_main_return` | true |
| Обрыв во время перехода | `handover.on_missing` | pause |
| Стабилизация после захвата: время и замеры | `handover.settle_seconds`, `settle_min_samples` | 3, 3 |

У переходов есть дополнительные условия в `rules`: включение, приоритет, исходные статусы, выдержка в статусе, число и время подтверждения, условия. В карточке записываются изменения **по имени правила**, например `switch_alternative`, а не по номеру строки массива. Задержку нельзя описывать только полем `handover.wait_seconds`, если правило добавляет собственное подтверждение.

## Как записать ожидаемый результат

Окрестность фильтра отвечает на вопрос «какую точку он принимает». Допуск испытания отвечает на вопрос «какой выход мы считаем приемлемым». Это разные условия. Ожидаемый результат не расширяется автоматически вслед за настройкой фильтра.

| Участок | Ожидаемый выход | Допустимая ошибка | От какого события считаем срок | Предельный срок |
|---|---|---|---|---|
| До готовности базы | Недоступен | Не применяется | Первый реальный замер | До выполнения условий накопления |
| Сопровождение исходной полки | Около исходного уровня | Задать в единицах измерения | Готовность базы | Задать |
| Первая верхняя полка | Около прежнего уровня, без захвата верхнего | Задать | Начало отклонений | Весь указанный участок |
| Обрыв | Пролонгация → недоступен → сброс | Задать ошибку прогноза | Выбранные часы обрыва | По выбранной политике; отдельно проверить границу таймаута |
| Новая полка после сброса | Накопление → сопровождение нового уровня | Задать | Первый замер после сброса | Задать |
| Возврат вниз | Переход на нижний уровень | Задать область допустимого перехода | Указать наблюдаемый сигнал возврата | Задать задержку и длительность |

Для каждой строки сравниваются фактическая траектория, доступность выхода и причина смены режима с записанным ожиданием. Нарушение хотя бы одной обязательной строки означает несоответствие этого сценария. Незаданный допуск или срок означает «оценить пока нельзя», а не успешный результат.

## Какие ещё сценарии нужны

Каждый вариант получает собственную карточку с входом, настройками и ожиданиями. Основной рисунок не заменяет их.

| Сценарий | Что изменяем | Что проверяем |
|---|---|---|
| Допустимая новая полка | Кандидат выполняет выбранные условия количества, времени и качества | Автономный захват без внешнего подтверждения |
| Столько же замеров за разное время | Одинаковое количество за короткий и длинный интервал | Количество не подменяет длительность; решение соответствует обоим условиям |
| Нулевая и ненулевая пролонгация | Меняем отдельно outlier_hold_seconds и gap_hold_seconds | Удержание действительно отключается или длится заданное время |
| Резкий и плавный переход | Меняем duration_seconds, curve и wait_seconds | Заданные ожидание и форма; промежуточные точки не считаются реальными наблюдениями |
| Полное и неполное окно | Меняем allow_partial и пороги partial_* | Переход разрешён только выбранной политикой |
| Неровные полки и помехи | Меняем шум, асимметрию и редкие далёкие точки | Контроль окрестности и качества в объявленной области применимости |
| Разрыв около временной границы | Точки до, на и после выбранной границы | Верное удержание, недоступность, сброс и новое накопление |
| Возврат или обрыв во время перехода | Прерываем переход соответствующим входом | Выбранные отмена, пауза или другая предусмотренная реакция |
| Остальные режимы и ошибочный вход | Отдельные короткие истории входа | Каждый предусмотренный режим и отказ; отсутствие случайной порчи памяти |

## Перечень того, что должно быть подтверждено

1. Первая зачёркнутая верхняя полка подавляется.
2. Возврат вниз соответствует разрешённым задержке и длительности.
3. Текущий статус однозначно определяет выполняемый режим.
4. Проверены также режимы, которых нет на рисунке.
5. Изменение настройки перехода действительно изменяет соответствующее поведение.
6. Допустимая новая полка захватывается автономно.
7. Недопустимая полка отвергается даже при достаточном количестве и времени.
8. Начальная база проверяется отдельно по количеству и длительности.
9. Альтернативная база и частичное окно проверяются по выбранной политике.
10. Используются реальные нерегулярные времена.
11. Окрестности основной и альтернативной полок задаются отдельно.
12. Неровные полки и ограниченная выборка проверяются в заявленной области помех.
13. Пролонгации отклонений и пропусков настраиваются отдельно, включая ноль.
14. Ожидание переключения и длительность перехода различаются.
15. Прогноз не создаёт новых наблюдений в базе.
16. Таймаут полностью очищает память на оговорённой границе.
17. После сброса накопление начинается заново.
18. После захвата соблюдается выбранная стабилизация и сопровождение.
19. Нет привязки к номиналам и абсолютным временам картинки.
20. Листинг объясняет фактические режимы и причины переходов.
21. Решения используют только доступное прошлое и текущий вход.
22. Ошибочные входы обрабатываются по контракту без непредусмотренной порчи состояния.
23. Признак доступности результата соответствует накоплению и пролонгации.

## Что предъявляется по окончании опыта

Одна карточка с фактически использованными входами и настройками, график с этапами и допустимыми областями, краткий результат по каждой строке ожиданий и листинг переходов с временем, статусом, измерением, выходом, доступностью и причиной.

Список посещённых статусов и число внутренних проверок не доказывают соответствие траектории. Прежний результат 5088 проверок не является подтверждением вашего рисунка.

## Связь с существующими испытаниями

- [filter2win_config.json](../matlab/tests/configs/filter2win_config.json) — настройки фильтра, указанные выше.
- [filter2win_system.json](../matlab/tests/configs/filter2win_system.json) — существующие параметры системных опытов и варианты переходов. Это текущие испытания, а не согласованная карточка вашего рисунка.
- [filter2win_demo_scenario.json](../matlab/tests/configs/filter2win_demo_scenario.json) — существующий генератор случайного демонстрационного входа; не полный основной сценарий выше.
- [filter2win_observations.json](../matlab/tests/configs/filter2win_observations.json) — параметры наблюдений, похожих на рисунок; происхождение точного входа ещё должно быть установлено.
