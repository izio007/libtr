# Предложения по развитию libtr

Каталог перспективных предложений для Главного аналитика. Предложения не
являются действующими регламентами, математическими паспортами или разрешением
на реализацию. После согласования математическое описание метода оформляется
в docs/ согласно PaeroPrincipe.md; производные представления создаются транслятором.

## Нумерация

- Одно предложение — один Markdown-файл с префиксом 01_, 02_, …, 99_.
- Следующий номер — следующий после наибольшего выделенного номера.
- Номера не переиспользуются и не меняются при изменении статуса предложения.
- Отклоненные и реализованные предложения сохраняются со своим статусом.
- После 99 требуется согласовать расширение нумерации, а не начинать ее заново.

## Запросы и результаты коммитов

Для каждого последующего коммита изменений добавляется нумерованная запись
запроса и результата: постановка пользователя, согласованные ограничения,
измененные файлы, выполненные проверки, ограничения и статус. Запись входит
в тот же коммит. Его идентификатор получают через git log -- <файл записи>:
вписывать собственный хеш внутрь коммита невозможно без изменения этого хеша.
Для нескольких коммитов одной задачи создаются отдельные записи с перекрестными
ссылками. История до введения правила восстанавливается только по доступным
материалам; неизвестные запросы не реконструируются предположениями.
Записи результатов не заменяют математические паспорта и действующие регламенты.
