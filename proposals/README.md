# Тематический указатель истории коммитов

proposals помогает найти постановку задачи, решения и результаты в Git.
Это не каталог действующих регламентов и не второй список незавершённых работ.

## Правила

- **Одна тема — один файл.** Продолжение темы дополняет её файл; новая тема получает новый файл.
- Новый коммит не требует нового файла. Внутри темы этапы располагаются хронологически.
- Запись этапа: задача, ограничения, полный индекс коммита, результат, выполненные проверки и ссылки на первоисточники.
- Для ещё не созданного коммита писать «не закоммичено», а не предполагаемый хеш. После фиксации индекс устанавливается по Git. Собственный хеш внутрь создаваемого коммита не вписывается.
- Старые пути, результаты и формулировки сохраняются как факты конкретного этапа, а не как текущие нормативные указания.
- **Открытые работы — в корневом need_work.md; решения Шефа — в need_chief.md.** В теме остаётся ссылка, а не конкурирующий текущий список.
- Идеи и проектные контракты хранятся в ideas/; математические первоисточники — в docs/. История ссылается на них, не копирует их содержание.
- Номера файлов — устойчивые идентификаторы тем; следующий номер больше ранее выделенных. Номер удалённой или объединённой темы не переиспользуется.
- Исторические результаты не доказывают актуальную приёмку. Отсутствующие сведения не восстанавливаются предположениями.
