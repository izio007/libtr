# Единое завершение выпуска filter2win

Причина повторных попыток: локальные PASS не агрегировались в итог выпуска;
финализатор безусловно оставлял NOT_RUN; очередь не отражала новые результаты.

Контракт исправления до проверки:
- отсутствие приёмки оставляет NOT_RUN, не требует повторять расчёты;
- явный FAILED имеет приоритет; PASS требует всех обязательных проверок;
- review связывается SHA-256 с байтами одного кандидата, включая отчёт исполнения;
- изменение байтов аннулирует review; чужой/старый review отвергается;
- новый процесс подтверждается и review, и фактическим отчётом;
- существующий выходной каталог отвергается до изменения метаданных кандидата.

Точка проверки: tools/runner.sh matlab/tests/configs/runner_contract.json.
Ядро, сценарии и требования ручного контроля не меняются.

Формат results/release_review.json: schema_version=1, package_version,
candidate_sha256 (tools/filter2win_acceptance.py: fingerprint), checks.
Обязательные checks: fresh_process, readability, html_visual, pdf_visual,
mlx_visual, png_visual. Каждый содержит status NOT_RUN/PASS/FAILED;
для выполненного check обязательны reviewer, evidence и criterion.
Это запись фактической проверки, не автоматическое согласование человеком.
Финализатор проверяет привязку и полноту записи, но не заменяет сам аудит.

Порядок продолжения: выбрать и сверить один кандидат с текущими исходниками;
для неизменных байтов использовать его отчёт, выполнить только недостающие
проверки, записать review, запустить финализатор. Новая попытка допускается
после конкретного исправления, а не для повторного получения уже имеющегося PASS.
Режим замены сервера остаётся решением F2W-HOST-01; повторное исполнение на
старом host его не закрывает. Неподтверждённая ручная приёмка не выдумывается.
