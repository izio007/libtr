# Контекст выделенного MATLAB-сервера

@CRITERION MATLAB-CONTEXT-001: перед заданием и каждым unit-тестом очищаются
base workspace, globals, незаблокированные функции/persistent и фигуры;
восстанавливаются стандартный путь, проектные пути и seed 1729, обновляется
кэш путей. TCP/timer и очередь живут в функциональном контексте сервера.
@CRITERION MATLAB-CONTEXT-002: изменение теста и его зависимости между двумя
TCP-заданиями исполняется без смены PID сервера. Загрязнение base/global/persistent
из первого задания не доступно второму.
Сервер выделенный: пользовательские переменные и фигуры в нём не сохраняются.
Не применять clear classes/delete(timerfindall): они затрагивают транспорт.
Активные и mlock-функции, классы с живыми экземплярами не гарантируются этой
очисткой. Изменение самого активного host/server требует отдельного перезапуска.
Это не доказательство происхождения всех исполняемых зависимостей.
service_pipeline_host не имеет таймаута 1800 секунд. Штатная остановка:
создать runtime/pipeline/stop-server, когда нет активных заданий.
@CRITERION CONTEXT-VERSION-001: запрос test_sha256 проверяется до постановки и после очистки; другой хеш для того же ID отклоняется. Отчёт содержит test_sha256, host_pid и context_protocol=2. Без поля прежний режим сохраняется. Проверяется только выбранный тест, не замыкание зависимостей.
