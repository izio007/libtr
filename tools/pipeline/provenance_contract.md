# Снимок явно объявленных входов запуска

Основание: ideas/01_provenance_impact_analysis.md, REQ-TRACE-PROV-001–005.
Первый срез: сбор снимка, не подтверждение фактически исполненного MATLAB-кода.
Вход — JSON schema_version=1, inputs: список {path, role}; пути относительно
корня. Манифест должен находиться вне runtime/. Выход — новый каталог runtime/.

@CRITERION PROV-SNAPSHOT-001: сохраняются полный Git SHA, dirty, Python/platform,
байты каждого объявленного входа, его роль и SHA-256; манифест входов имеет
детерминированную сериализацию и внешний хеш. Исходники не меняются.
@CRITERION PROV-SNAPSHOT-002: абсолютные/выходящие за корень пути, runtime-входы,
дубликаты, пустые роли и отсутствующие файлы отклоняются. Существующий каталог
не перезаписывается. Частичный сбор не публикует завершённый manifest.json.
@CRITERION PROV-SNAPSHOT-003: изменение или удаление объявленного входа после
снимка обнаруживается повторным хешированием независимо от mtime. Байты снимка
сохраняются. Сравнение до/после не обнаруживает изменение с последующим возвратом.

coverage=explicit_only; execution_status=NOT_RUN; verification_status=NOT_RUN;
loaded_code_identity=unconfirmed. Снимок не является свидетельством запуска из
него. Изоляция исполнения, состояние RNG и полнота зависимостей остаются
отдельными задачами. Поля среды относятся к сборщику, не MATLAB.

## Необязательное сопровождение TCP-клиента

@CRITERION PROV-TCP-001: при --provenance-spec и --provenance-output клиент
сохраняет снимок и запрос ДО submit. Без этих опций прежний протокол сохранён.
Декларация входов должна находиться внутри проекта вне runtime/; её байты
также входят в снимок. Каталог попытки уникален и не перезаписывается.
@CRITERION PROV-TCP-002: после ответа или исключения клиента публикуется отдельная
запись attempt.json: запрос, хеш манифеста, ответ сервера либо ошибка клиента,
изменённые входы или ошибка сверки. Исходный manifest.json не переписывается.
При изменении входов успешный ответ сервера сохраняется, но exit code клиента
не равен нулю. Состояние MATLAB-кода остаётся unconfirmed даже при совпадении.
@CRITERION PROV-TCP-003: ошибка связи/таймаут не выдаётся за провал математического
check и не утверждает отмену серверного задания. Повторный submit не выполняется.
Повторное использование ID может вернуть прежний ответ: попытка клиента не
доказывает новый запуск. Поэтому актуальность всегда UNCONFIRMED, автоматического
CURRENT или переноса серверного passed в verification_status нет.

## Реестр артефактов завершённого задания

@CRITERION PROV-ART-001: отдельный CLI читает attempt.json, сопоставляет ID,
action и test с серверным request.json и ID/action/state с report.json.
При незавершённом задании или несовпадении реестр не публикуется.
@CRITERION PROV-ART-002: все объявленные артефакты должны существовать внутри
каталога задания; обходы пути, абсолютные пути и дубликаты запрещены. Реестр
содержит размер и SHA-256 фактических байтов, Git SHA снимка, хеши attempt и
manifest. Их связь не доказывает происхождение исполнения: UNCONFIRMED.
@CRITERION PROV-ART-003: проверка реестра обнаруживает изменение и отсутствие
файла. Реестр публикуется вне каталога задания без перезаписи, не хеширует себя,
не меняет исходный отчёт. Повторное получение старого результата не становится
новым запуском. Проверяется только объявленный набор, не полнота артефактов.

@CRITERION PROV-ART-004: сопровождаемый TCP-клиент после записи attempt.json
автоматически публикует artifacts.json и отдельный artifact_status.json.
Ошибка реестра блокирует успешный код клиента, но не меняет серверный результат.
При исключении связи инвентаризация NOT_RUN; исходное исключение сохраняется.
Каталог попытки запрещён внутри runtime/pipeline/, чтобы не менять файлы задания.
Успешная инвентаризация не означает PASS математических checks или CURRENT.
