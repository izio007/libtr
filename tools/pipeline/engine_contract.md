# Движок исполнения pipeline

Область: последовательное исполнение зарегистрированных этапов, транспорт,
дедлайн, отчёт и отказ. Не содержит математики, настройки сценариев, экспорта
или правил приёмки продукта. Python standard library; Cygwin Python 3.12.

- engine.py: JSON Lines transport, единственный submit/poll, Pipeline.
- declarative_runner.py: строгая конфигурация и регистрация исполнителей.
- pipeline_client.py: совместимый CLI для существующих потребителей provenance.
- filter2win_package_runner.py: проверка идентичности автономного host и адаптер.
- MATLAB host: существующий последовательный исполнитель; его жизненный цикл
  не меняется данным рефакторингом.

Критерии до реализации, проверяются pipeline_engine_runner.json:
1. Каждый этап изначально NOT_RUN; только нормальный возврат даёт PASS.
2. Первый отказ останавливает исполнение, последующие этапы остаются NOT_RUN.
3. Отчёт содержит hash конфигурации и атомарно сохраняется между этапами.
4. Defect Snapshot с traceback и job id сохраняется без перезаписи;
   неизвестные expected/actual/RNG обозначаются null, не придумываются.
5. submit ровно один; timeout status можно повторить только внутри общего
   дедлайна. Неопределённость доставки submit не вызывает повторную отправку.
6. Дедлайн не выдаёт cancel за выполненную отмену. MATLAB кооперативен;
   job id сохраняется, сервер не уничтожается и новый процесс не создаётся.
7. Busy host отклоняется до submit для любого зарегистрированного MATLAB suite.
8. Успешный stdout — только агрегированная строка; подробности в JSON.

Не удаляются используемые реестры, provenance и трассируемость. Их импорт
не должен быть транзитивной зависимостью штатного движка исполнения.
Старые архивы не переписываются. Сетевой протокол совместим с текущим host.
