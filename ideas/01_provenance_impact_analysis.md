# 01. Происхождение результатов и адресная инвалидация

## Статус и область действия

Проектный контракт, зафиксированный по обсуждению с Шефом. Предназначен для
Zero-DB конвейера прослеживаемости libtr при масштабе до 1M LOC.
Реализация требований ниже этим документом не подтверждается.
Изменения математических методов и внедрение нового конвейера в эту фиксацию
не входят. Первичные данные версионируются либо сохраняются воспроизводимым
снимком; производные индексы и отчеты размещаются в runtime/.

## 1. Основные различия

- Происхождение: на каких фактических входах получен результат.
- Применимость: пригоден ли этот результат для текущего состояния проекта.
- Исполнение: завершился ли процесс проверки.
- Проверка утверждений: выполнен ли математический или программный критерий.

Успешное исполнение не означает PASS утверждений. Наличие связи с тестом
не означает прохождения теста. Изменение зависимости не означает FAIL:
оно может сделать прежнее свидетельство устаревшим (STALE).

## 2. Контракт происхождения (Provenance)

[REQ-TRACE-PROV-001] Каждый run и artifact содержит полный git_sha базовой
ревизии, а не сокращенный хеш и не время изменения файлов.

[REQ-TRACE-PROV-002] Для запуска сохраняется манифест фактически использованных
входов: относительные пути, SHA-256 содержимого, роли входов и зависимости.
Включаются исходники, спецификации, конфигурации, инструменты проверки,
эталонные данные и внешние наблюдения. Для случайных расчетов фиксируются
алгоритм генератора и его состояние либо сами входные наблюдения.

[REQ-TRACE-PROV-003] Рабочее дерево обозначается как clean или dirty.
При dirty git_sha идентифицирует только базу. Измененные и необходимые
неотслеживаемые входы сохраняются воспроизводимым снимком; один хеш без
доступного содержимого не обеспечивает воспроизводимость.

[REQ-TRACE-PROV-004] Фиксируются среда, версии инструментов, параметры сборки
и расчета. Результат связывается с неизменяемым снимком входов. Если входы
изменились во время запуска и снимок не был изолирован, происхождение
считается неподтвержденным, а не автоматически CURRENT.

Минимальные поля сущностей:

| Сущность | Поля |
|---|---|
| run | id, git_sha, dirty, input_manifest_sha256, configuration_sha256, environment_id, execution_status, verification_status |
| artifact | id, run_id, git_sha, input_manifest_sha256, content_sha256 |

[REQ-TRACE-PROV-005] Хеш артефакта вычисляется по его фактическим байтам;
ссылка на хеш хранится во внешней записи, без самоссылочного хеширования.
Манифест сериализуется детерминированно; версия формата фиксируется.

[REQ-TRACE-PROV-006] Исторический git_sha результата не переписывается после
нового коммита. Применимость к новой ревизии оформляется отдельной записью
со ссылкой на исходный run и основанием повторного использования.

Хеши подтверждают идентичность материалов, но сами по себе не доказывают
подлинность исполнения. Подписание результатов — отдельное решение.
mtime может служить подсказкой быстрого поиска изменений, но не доказательством
неизменности. Предусматривается режим полной проверки содержимого.

## 3. Логические блоки и нормативность

[REQ-TRACE-IMPACT-001] Единица содержательного анализа — блок со стабильным ID,
типом, содержимым, хешем и зависимостями. Файловый SHA-256 сохраняется для
контроля целостности и повторного разбора; блочный хеш определяет влияние.

| Тип блока | Влияние изменения |
|---|---|
| Явно ненормативное пояснение | Пересборка документа, без инвалидации расчетов |
| Формула | Перепроверка зависимых реализаций и проверок |
| Контракт входов, единиц, статусов или порядка вычислений | Инвалидация зависимых свидетельств |
| Критерий приемки | Инвалидация результатов соответствующих проверок |
| Методика, геометрия, шум, объем ансамбля | Инвалидация затронутых экспериментов |

[REQ-TRACE-IMPACT-002] Обычный текст не считается ненормативным по умолчанию.
Изменение единиц, отрицания или условий отказа меняет контракт даже без LaTeX.
Неопределенные блоки обрабатываются консервативно. Изменение типа блока также
учитывается при анализе влияния.

[REQ-TRACE-IMPACT-003] Нормализация версионируется и не подменяет доказательство
эквивалентности выражений. Неизвестное преобразование считается изменением.
Повторные ID, удаление блоков, оборванные ссылки и изменение зависимостей
диагностируются явно. Перенос блока без изменения содержания не должен терять
его идентичность, но пути и ссылки проверяются заново.

## 4. Алгоритм адресной инвалидации

1. Определить добавленные, измененные, удаленные и перемещенные файлы.
2. Повторно разобрать затронутые файлы; сравнить блоки по ID, типам и хешам.
3. Построить изменение графа с учетом прежних и новых связей, в том числе
   зависимостей удаленных блоков.
4. Обойти обратные зависимости измененных нормативных блоков.
5. Обозначить затронутые свидетельства STALE; остальные сохранить применимыми
   при неизменности всех их входов и среды, существенных для проверки.
6. Опубликовать причины инвалидации и цепочку зависимостей.

[REQ-TRACE-IMPACT-004] Изменения кода теста, ядра, общего сервиса, конфигурации,
генератора наблюдений и среды проверки также входят в анализ влияния.
Блочный анализ документов не освобождает от учета этих зависимостей.

[REQ-TRACE-IMPACT-005] Изменение версии парсера, правил нормализации или схемы
графа инвалидирует несовместимый кэш. Отсутствующий или поврежденный кэш
восстанавливается из первоисточников. Неопределенная полнота зависимостей
не дает права присваивать CURRENT.

## 5. Состояния и доказательства

Состояния связи, исполнения, утверждений и актуальности хранятся раздельно.
Например, исторический PASS может иметь актуальность STALE. Ошибка связи
ORPHAN не является результатом численного теста. Отсутствующий запуск не PASS.

[REQ-TRACE-RESULT-001] PASS/FAIL определяется проверкой объявленного критерия
на зафиксированных входах. Изменение документа или истечение времени само
по себе не меняет исторический результат утверждений.

## 6. Приемочные проверки будущей реализации

- Чистое дерево: run и artifact имеют одну ревизию и проверяемые хеши входов.
- Dirty-дерево: сохраненный снимок воспроизводится независимо от последующего
  изменения рабочей копии; базовая ревизия не выдается за весь снимок.
- Переключение ветки с изменением mtime не создает ложной актуальности.
- Правка явно ненормативной опечатки пересобирает документ, не инвалидируя расчет.
- Изменение формулы, единиц, статуса или критерия инвалидирует только зависимые
  свидетельства; изменение общего сервиса распространяется по обратным связям.
- Удаление блока и ребра проверяется по старому и новому графам.
- Повторные ID и неизвестные зависимости дают диагностику, а не тихий PASS.
- Изменение входов во время расчета обнаруживается либо исключается снимком.
- Изменение байтов артефакта обнаруживается проверкой content_sha256.
- Утрата кэша не меняет смысл полного результата реконструкции графа.

Холодный запуск, горячий запуск, изменение одного блока и полная проверка
измеряются отдельно на фиксированном стенде. Доли секунды и масштаб 1M LOC —
целевые характеристики, не подтвержденные гарантии. Набор проверок выше является
планом приемки, а не отчетом об уже выполненных испытаниях.
